# OPTRANE Lovable gateway

## Public hosts

- Canonical OPTRANE website: `https://film-sparkle-layer.lovable.app`
- Desktop namespace: `/api/public/itrain-api`

## Network model

```text
OPTRANE Command
  |
  | OPTRANE user bearer session
  v
OPTRANE Lovable API
  |
  +-- account/session broker
  +-- production state + private storage
  +-- governed agent broker
  +-- Google Agent Runtime / ADK / Gemini
  +-- official mcp-clickhouse
  +-- ClickHouse Cloud
  |
  v
normalized result/evidence
```

The desktop bundle contains only the Lovable OPTRANE host. It does not contain a provider-native governance URL, Google endpoint credential, ClickHouse credential, MCP token, service-role key or peer signing key.

## Website verification

Human registration/login is website-first. Desktop pairing uses a high-entropy verifier generated by the gateway. The deep link carries only `request_id`, while the verifier stays in desktop session memory until exchange. The OPTRANE gateway consumes its server-held one-time identity token and returns a normal OPTRANE user session exactly once.

The desktop itself contains no password form in production mode and no identity-provider SDK.

## Private peer

Provider-native governance peer setup is backend-only. OPTRANE uses:

- Basic client credentials only for initial claim over TLS.
- Ed25519 proof of possession for the claim challenge.
- Ed25519 signatures over `METHOD\nPATH\nSHA256(BODY)\nTIMESTAMP\nNONCE` for each peer request.
- ±60 second timestamp validation.
- one-use nonce replay protection.
- signature-verified webhooks with event replay protection.

No claim, verify, ping, close or native provider API route is callable from the Tauri client.
